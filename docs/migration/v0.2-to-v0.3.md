# v0.2 → v0.3 升级 walkthrough

forge v0.3 切换到 plugin 形态(三 harness 全 unblock,Plan 0a 实测验证)。本 walkthrough 给 v0.2 用户清晰的迁移路径,**`forge/` 产物 100% 不丢**(drafts / changes / specs / config 全保留)。

## 何时需要升级

如果你的项目跑过 `forge init --harness <claude|codex>`,会有以下 legacy 产物:

```
<project>/
├── .claude/skills/forge-{using-forge,brainstorming,...}/SKILL.md  ← Claude legacy
├── .claude/commands/forge/{brainstorm,propose,...}.md             ← Claude legacy
├── .agents/skills/forge-*/SKILL.md                                 ← Codex legacy
├── .agents/commands/forge/*.md                                     ← Codex legacy
└── forge/                                                          ← 用户产物(必须保留)
    ├── config.yaml
    ├── drafts/
    ├── changes/
    └── specs/
```

v0.3 plugin 路径不再用项目级 `.claude/skills/forge-*/` 等(plugin namespace 替代)。`forge upgrade` 命令 5 阶段事务清理 legacy 产物 + 输出 plugin install 指引。

## Step 1:升 npm CLI(本地)

```bash
npm i -g @accelerator-mzq/forge@0.3.0
forge --version    # 应输出 0.3.0
```

## Step 2:跑 `forge upgrade`(项目内)

```bash
cd <your v0.2 project>
forge upgrade
```

5 阶段事务流程:

```

  .claude/skills/forge-brainstorming/SKILL.md (sha256: a1b2c3d4...)

  ...
  .agents/skills/forge-brainstorming/SKILL.md (sha256: ...)
  ...
  .claude/commands/forge/brainstorm.md (sha256: ...)
  ...

```

## Step 3:装 plugin(三 harness 各一)

按 [installation.md](../installation.md) 选 Tier 装。Tier 1 Claude Code 推荐:

```
# Claude Code session 内
/plugin marketplace add Accelerator-mzq/forge
/plugin install forge@accelerator-mzq-forge
/reload-plugins
```

`/exit` + `claude` 重启,验证 brainstorming auto-trigger:

```
我想做个 todo list 应用
```

预期 AI 自动 invoke `Skill(forge:brainstorming)`(同 v0.2 fixture P0 修复后的预期行为,Plan 0b.1 实测 PASS)。

## Step 4:验证 forge/ 产物完整

```bash
ls forge/
# 应见:config.yaml + drafts/ + changes/ + specs/ + .cache/ 全部如初
```

如果有正在进行的 change(`forge/changes/<id>/.verify-passed` 已打但 review 未跑),v0.3 plugin 装好后**直接继续走** `/forge:review` 即可,marker 与 hash 100% 保留(Plan 4 实测 case 3 验证)。

## Step 5(可选):24h 内 recover

如果上面 Step 2 跑后发现问题(plugin 装失败 / 想回 v0.2 路径),24h 内可还原:

```bash
forge upgrade --recover
# 全部 legacy 产物 mv 回原位 + 验 hash + 删 stash
```

>24h 后 stash 自动失效(`forge upgrade --gc` 清理):

```bash
forge upgrade --gc
# Deleted N expired stashes.
```

## Step 6(可选):跨 plugin 共存

forge plugin 可与 superpowers plugin 同装。每个 harness 处理方式略不同:

- **Claude Code**:fixture 项目级 enable,`.claude/settings.local.json` 控制哪个 plugin 启用
- **OpenCode**:`opencode.json` plugin 数组顺序;移除 entry 即 disable
- **Codex**:不支持显式 disable;两个都装 + 装两 plugin namespace 共存,description differentiator 决定 AI 选哪个;不稳定时 `rm ~/.agents/skills/<plugin>` 单 disable

详见各 harness install 文档"Cross-plugin"段。

## v0.4 即将移除 `forge init`

v0.3 `forge init` 仍能跑(legacy 兼容窗口),但 stderr 打 deprecation warning。v0.4 完全移除 — 新项目应直接装 plugin,不要再走 `forge init` 路径。

## 升级后 P2/P3 行为变化

**P2 brainstorming 修复**:空 git repo / 无 `.gitignore` 时,brainstorming skill 主动询问 git base,不静默 commit draft(v0.2 fixture 测试发现的 silent commit 问题已修)。

**P3 writing-plans scale-aware**:trivial change(proposal < 200 行 / `--light` flag)走 light mode(1-2 task,跳 RED/GREEN/REFACTOR);full change 走原 5+ task 完整模板。可在 `forge/config.yaml` 改 threshold:

```yaml
writing_plans:
  light_threshold: 100   # 默认 200,允许 50-2000
```

(v0.2 用户跑 `/forge:propose` 时如果原 trivial change 产 511 行 / 1378 行 tasks.md,v0.3 会自动走 light mode 产 ~80 行,不再过度生成)

## 故障

任一 step 出问题,贴 transcript 到 https://github.com/Accelerator-mzq/forge/issues 报 issue。

`forge upgrade` 在 ASK 阶段前完全只读,N 时 0 副作用 — 你可以反复跑测试不怕污染。
