## 1. 顶层架构

### 1.1 仓库形态:单仓库 + 多 plugin manifest

参考 superpowers(`.claude-plugin/` + `.codex-plugin/` + `.opencode/plugins/` 共住一仓),v0.3 forge 仍是**单仓库**(`Accelerator-mzq/forge`),原有 npm 包发布路径不变,根目录加 plugin manifest 后**同时是 plugin marketplace 源**:

```
Accelerator-mzq/forge/                    ← 仓库 = npm 源 + plugin marketplace
├── .claude-plugin/
│   ├── plugin.json                       ← Claude Code plugin manifest (decision #25)
│   └── marketplace.json                  ← 自建 marketplace(decision #23),列出 forge plugin
├── .codex-plugin/
│   └── plugin.json                       ← Codex plugin manifest (decision #25)
├── .opencode/
│   └── plugins/
│       └── forge.js                      ← OpenCode JS hook (decision #25)
├── skills/                               ← ★ NEW:plugin-facing skill 文本(从 src/core/templates/skills/ 提上来)
│   ├── using-forge/SKILL.md
│   ├── brainstorming/SKILL.md
│   └── ... 12 个
├── commands/                             ← ★ NEW:plugin-facing 6 commands
│   ├── brainstorm.md
│   ├── propose.md
│   ├── apply.md
│   ├── review.md
│   ├── verify.md
│   └── archive.md
├── hooks/                                ← ★ NEW:session-start hook(注入 using-forge bootstrap)

├── dist/                                 ← npm CLI 构建产物(原,不进 git,gitignored)
```

### 1.2 单一 source of truth — skills/ + commands/

**关键变化(decision #26):skills/ 与 commands/ 从 `src/core/templates/` 提到仓库顶层**。

| 现状(v0.2)                                   | v0.3                                                            |
| ----------------------------------------------- | --------------------------------------------------------------- |
| `src/core/templates/skills/forge-brainstorming.md` | `skills/brainstorming/SKILL.md`                                  |
| `src/core/templates/commands/brainstorm.md`     | `commands/brainstorm.md`                                         |
| 由 `harness-adapters/claude.ts` 在 `forge init` 时**写入项目** `.claude/skills/forge-*/` | plugin 加载时 Claude Code **直接从 plugin 仓库根** `skills/` 读 |

`scripts/copy-templates.mjs` 反向工作:在 `pnpm build` 时把仓库根 `skills/` + `commands/` 拷贝进 `src/core/templates/`(legacy `forge init` 路径仍能为 v0.2 用户铺老形态,但 `forge init` 在 v0.3 标记 deprecated,见 §1.4)。

### 1.3 双 plugin 变体 — 主 plugin vs bundled plugin(decision #24)

| 形态                  | name            | 适用 harness                | 分发                                                                                | CLI 调用                                                                                       | 体积                  |
| --------------------- | --------------- | -------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | --------------------- |
| **主 plugin(默认)**  | `forge`         | Claude Code / OpenCode / Codex | `marketplace.json` 列出 → 用户 `/plugin marketplace add Accelerator-mzq/forge`(Codex 走 git clone + symlink) | commands / skill 文本调 `node ${CLAUDE_PLUGIN_ROOT}/scripts/run-forge.mjs ...`(用户机要 Node 20+ 与网) | < 1 MB(纯 markdown + JS hook) |
| **bundled plugin(变体)** | `forge-bundled` | **仅 Claude Code**          | GitHub Release **附 tarball**(`forge-bundled-v0.3.0.tgz`),用户手动 `/plugin install` from URL | tarball 内含 `dist/`,build 期把 `run-forge.mjs` patch 为 `node ${CLAUDE_PLUGIN_ROOT}/dist/cli/index.js ...` | ~5 MB(含 dist)        |

**bundled 仅 Claude Code 的原因**:

- Claude Code plugin 加载时注入 `${CLAUDE_PLUGIN_ROOT}` env var(已实测,见 superpowers `hooks.json:9`)→ bundled 内嵌 `dist/` 路径可用
- OpenCode plugin 内 `__dirname` 可解,但 air-gapped + OpenCode 是低概率组合,v0.3 不做 OpenCode bundled。**air-gapped OpenCode 用户的 fallback 路径(具体形态由 Plan 0a.3 验证决定)**:Tier 2 启用时,在 release notes 列出 `~/.config/opencode/plugins/forge` 目录手动放入 plugin tarball 的步骤,**不**承诺 `npm i -D` 等价(superpowers 的 OpenCode 安装是配 `opencode.json` plugin entry,不是 node_modules 加载,等价说法待证)
- Codex 走 clone + symlink 路径,**没有** plugin env var 注入机制 — bundled 概念在 Codex 下不成立(用户已 clone 了完整仓库,要离线只需 `npm i -g` 离线 tarball,bundled plugin 是冗余)

bundled 不进 marketplace.json(避免误装),air-gapped Claude Code 用户走 README 指引手动 `/plugin install --from-tarball <path>`。`scripts/build-bundled-plugin.mjs` 在 release-gate 通过后从 npm pack 输出抽 `dist/` + 仓库 `skills/` + `commands/` + `hooks/` + `.claude-plugin/` manifest + patch 后的 `run-forge.mjs` 重打包(只含 Claude Code 部分,剥离 `.codex-plugin/` + `.opencode/`)。

### 1.4 v0.2 兼容窗口

- `forge init`(v0.2 老命令)在 v0.3 仍存在但**打 deprecation warning**(stderr 提示用户改装 plugin)
- `forge upgrade`(decision #27,新命令)在 v0.3 加,扫 `.claude/skills/forge-*/` + `.claude/commands/forge/` + `.agents/skills/forge-*/` + `.agents/commands/forge/`(实际 v0.2 codex adapter 写的是 `.agents/`,不是 `.codex/`),**仅扫描 + 列清单 + 提示 + 询问后删**(不静默 rm)
- v0.4 移除 `forge init` 老路径,完全切到 plugin

### 1.5 三个不可妥协原则(继承 v0.1 §1.2)

1. **CLI 不写业务逻辑** — 不变
2. **Harness Adapter 是单一接口** — v0.3 略松绑:plugin 形态下 adapter 主要负责 `forge upgrade` 的检测 + clean,而不是首次铺文件(plugin 自己铺)。`installSkills()` / `installCommands()` 标记为 v0.2-legacy,新增 `detectLegacyArtifacts()` / `cleanupLegacy()`
3. **产物目录用 `forge/`** — 不变

**Codex 路径范围限定 — `/forge:*` slash commands 不可用(Plan 0a.2 实测确认)**:

- superpowers `.codex-plugin/plugin.json` 只声明 `"skills": "./skills/"`;**Plan 0a.2 实测**:`/test:test` 报 "Unrecognized command",**Codex 不支持 plugin commands 注册**
- 因此 Codex 下 v0.3 **只支持 auto-trigger skills**(brainstorming / writing-plans / etc 自动触发),**不支持 `/forge:propose` 等显式 slash 命令**
- **literal `!command` 协议不存在**(Plan 0a.2 Variant A 实测 IGNORED — AI 把 `!echo ...` 当字符串 echo,不是 literal 自动执行)
- **真实可行机制 — skill 文本内嵌 fenced bash + must-execute 指示**(Plan 0a.2 Variant B/C 实测 PASS):skill body 写
  ````markdown
  When triggered, you **MUST** execute the following and include output verbatim:
  ```bash
  node ~/.codex/forge/scripts/run-forge.mjs validate <id>
  ```
  ````
  Codex AI 主动跑 PowerShell/bash + report 输出 — 这是严格门禁的 Codex 实现路径
- helper 内部用 `os.homedir()` 解析 Codex clone 根路径(跨平台一致);允许 `FORGE_CODEX_ROOT` env override |
- skill 文本 fork 到 `skills/<name>/SKILL.md` 时统一处理:Claude Code / OpenCode 路径 commands.md 调 npx,Codex 路径 skill 文本调 npx,语义一致

**Plan 0a 协议 spike 必须验证的 Codex 行为**:

- (a) `~/.agents/skills/<plugin>/<skill>/SKILL.md` 是否真进 Codex auto-trigger 池 ✓ superpowers 已实测
- (b) Codex 是否支持 plugin commands 注册(本地资料未见;若 spike 发现支持 → 后续 v0.4 加 commands 路径) ✗ 需验证
- (c) Codex 下 skill body 内 shell 调用(`!command` 或类似)是否能 invoke `npx` ✗ 需验证

(b)(c) 任一 fail → Codex 路径退到"只 skill,工作流靠 AI 内化",不影响 v0.3 ship。

#### 2.2.3 OpenCode:`.opencode/plugins/forge.js`(JS hook)

OpenCode plugin 是命名 export 的 async function,**不是 default export object**。两个 hook(对齐 superpowers 实测形态):

```js
// .opencode/plugins/forge.js
// 形态全部对齐 superpowers/.opencode/plugins/superpowers.js,不是想当然

import path from 'path';
import fs from 'fs';
import os from 'os';
import { fileURLToPath } from 'url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));

// 提取并剥离 SKILL.md frontmatter(用 using-forge 的 body 注入)
const extractAndStripFrontmatter = (content) => {
  const match = content.match(/^---\n([\s\S]*?)\n---\n([\s\S]*)$/);
  return match ? { body: match[2] } : { body: content };
};

export const ForgePlugin = async ({ client, directory }) => {
  const forgeSkillsDir = path.resolve(__dirname, '../../skills');

  const getBootstrapContent = () => {
    const skillPath = path.join(forgeSkillsDir, 'using-forge', 'SKILL.md');
    if (!fs.existsSync(skillPath)) return null;
    const { body } = extractAndStripFrontmatter(
      fs.readFileSync(skillPath, 'utf8'),
    );
    return `<EXTREMELY_IMPORTANT>\nYou have forge.\n\n${body}\n</EXTREMELY_IMPORTANT>`;
  };

  return {
    // Hook 1:把 forge skills 目录注入 OpenCode live config
    // → OpenCode 原生 skill discovery 自动找到,用户免 symlink(参考 superpowers 实战)
    config: async (config) => {
      config.skills = config.skills || {};
      config.skills.paths = config.skills.paths || [];
      if (!config.skills.paths.includes(forgeSkillsDir)) {
        config.skills.paths.push(forgeSkillsDir);
      }
    },

    // Hook 2:在每个 session 的 first user message 注入 bootstrap
    // 注意:注入 user message 而非 system message —— superpowers 实测踩过的坑:
    //   - system message 每 turn 重复 → token bloat(superpowers issue #750)
    //   - 多 system message 破 Qwen 等模型(issue #894)
    'experimental.chat.messages.transform': async (_input, output) => {
      const bootstrap = getBootstrapContent();
      if (!bootstrap || !output.messages.length) return;
      const firstUser = output.messages.find((m) => m.info.role === 'user');
      if (!firstUser || !firstUser.parts.length) return;
      // 已注入则跳过(防重复)
      if (
        firstUser.parts.some(
          (p) => p.type === 'text' && p.text.includes('EXTREMELY_IMPORTANT'),
        )
      )
        return;
      const ref = firstUser.parts[0];
      firstUser.parts.unshift({ ...ref, type: 'text', text: bootstrap });
    },
  };
};
```

**关键 4 处全部对齐 superpowers**:

1. 命名 export `ForgePlugin`(async function),**不是** `export default {...}`
2. hook key 是字符串 `'experimental.chat.messages.transform'`,签名 `(_input, output)`
3. 修改 `output.messages` 里 first user message 的 `parts`(把 bootstrap 作为新 part `unshift` 到最前),**不注入 system message**(原因见代码注释)
4. 第二个 hook `config` 注入 skills.paths 让 OpenCode 自动发现 forge skills,**用户免 symlink**(superpowers 实战获得的额外好处)

**实施基线**:fork superpowers `.opencode/plugins/superpowers.js`,改 plugin 名 / skill 名 / 警告文本,核心逻辑原样保留。

**OpenCode + Codex 路径 commands 替代设计**(Plan 0a 实测确认两 harness 都不支持 plugin commands 注册):每个 skill 文本(`skills/<skill-name>/SKILL.md`)末尾追加 **fenced bash + must-execute 段**,AI auto-trigger skill 后主动跑 helper。例:

````markdown
## Validation step (auto-execute when skill triggered)

When this skill completes its main flow, you **MUST** execute the following and include output verbatim:

```bash
node "$FORGE_HELPER" validate <change-id>
```

`$FORGE_HELPER` 在 OpenCode = `<plugin_dir>/scripts/run-forge.mjs`;Codex = `~/.codex/forge/scripts/run-forge.mjs`(`os.homedir()` 解析)。
````

**Codex / OpenCode 路径下** `/forge:*` slash commands 不可用(Plan 0a.2/0a.3 实测确认两 harness 都不支持 plugin commands 注册):skill 文本内嵌 fenced bash + must-execute 指示形态(参考 §2.2.2 的 markdown 模板),AI 在 auto-trigger skill 后**主动**调 `scripts/run-forge.mjs` helper(用 `os.homedir()` + `~/.codex/forge` 或 OpenCode plugin 根定位 helper)。

**bundled plugin 变体**:`scripts/build-bundled-plugin.mjs` 在打包时把 `scripts/run-forge.mjs` 头部 `REQUIRED_RANGE` 替换为 `node ${CLAUDE_PLUGIN_ROOT}/dist/cli/index.js` 的内嵌调用(spawn args 改 `node` + `${CLAUDE_PLUGIN_ROOT}/dist/cli/index.js` + ...args),replace 在 build 期一次性做,不需运行时分支。`${CLAUDE_PLUGIN_ROOT}` 由 Claude Code plugin 加载时注入(参见 [`CLAUDE_PLUGIN_ROOT`](https://docs.anthropic.com/claude/docs/plugins) 官方文档,与 superpowers 实测一致)。

### 2.5 hooks/ — session-start 注入(Claude Code only)

形态全部对齐 superpowers 实战,**不是想当然**。三个文件:

```json
// hooks/hooks.json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|clear|compact",
        "hooks": [
          {
            "type": "command",
            "command": "\"${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.cmd\" session-start",
            "async": false
          }
        ]
      }
    ]
  }
}
```

```bat
:: hooks/run-hook.cmd — cross-platform polyglot(:: 是 cmd 注释,bash 里是 no-op)
:: 内嵌 cmd batch 段:Windows 下 cmd.exe 跑;Unix 下 bash 跳过 batch 段执行尾部 exec
:: 见 superpowers/hooks/run-hook.cmd 的完整实现,fork 即可
```

```bash
# hooks/session-start —— 注意:无 .sh 扩展名(Claude Code Windows 自动检测会给 .sh 文件强加 bash 前缀,polyglot 失效)
# 内容:cat ${PLUGIN_ROOT}/skills/using-forge/SKILL.md → escape JSON → 输出 hookSpecificOutput.additionalContext
# 见 superpowers/hooks/session-start 的完整实现,fork 即可
```

**关键 4 处全部对齐 superpowers**:

1. 变量是 `${CLAUDE_PLUGIN_ROOT}`,**不是** `${CLAUDE_PLUGIN_DIR}`(后者是 Claude Code 旧文档残留,plugin spec 里不存在)
2. `SessionStart` 数组元素是 `{matcher, hooks: [...]}` 嵌套结构,有 `matcher: "startup|clear|compact"` 控制触发时机
3. command 必须双引号包(路径含空格 / `${CLAUDE_PLUGIN_ROOT}` 展开后可能含特殊字符);`async: false` 保证 hook 完成才进 session
4. hook 脚本是 `run-hook.cmd` polyglot wrapper(同时为 cmd batch 与 bash 脚本)+ 真实业务脚本 `session-start`(无扩展名),不是裸 `session-start.sh`

业务脚本 `session-start` 输出 JSON `{"hookSpecificOutput": {"additionalContext": "<using-forge content>"}}` 到 stdout,Claude Code 解析并把 `additionalContext` 注入 system prompt 段。**这是 P0 的加固层(decision #28 中的 hook fallback 路径)** — 让 `using-forge` bootstrap 在 session start 必然进 system prompt,不靠 skill auto-trigger 池单边保证。

OpenCode 走 `forge.js` 的 `'experimental.chat.messages.transform'` 等价机制(§2.2.3);Codex 通过 `~/.agents/skills/forge` symlink 让 Codex 原生 skill discovery 找到(无需 hooks)。

**实施基线**:fork superpowers `hooks/{hooks.json,run-hook.cmd,session-start}` 三文件,改 `using-superpowers` 为 `using-forge`,其余原样保留(legacy 兼容警告等可裁剪)。

## 4. 错误处理与不变量

### 4.1 `forge upgrade` 事务化

5 阶段:**SCAN → SHOW DIFF → ASK → STASH → VERIFY → COMMIT**(详细数据流见 §3.2)。

| 阶段        | 动作                                                                                                  | 失败处理                                                                       | 副作用 |
| ----------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------ |
| SCAN        | 调三 adapter 的 `detectLegacyArtifacts(projectRoot)`,收集路径 + 算 sha256                            | 文件读失败 → 报错退出                                                          | ❌ 无  |
| SHOW DIFF   | stdout 列清单 + hash;`show-diff` 子选项展开每文件 diff                                                | —                                                                              | ❌ 无  |
| ASK         | 等用户输入 y / N / show-diff                                                                          | Ctrl+C / N → 立即退出                                                          | ❌ 无  |
| STASH       | 收集所有 legacy 路径,逐一 `mv` 到 `<project>/.forge-upgrade-stash-<ts>/`,写 `.manifest.json`         | 任一 mv 失败 → 反向 mv 已 stash 的回原位 → 退出非零                             | ⚠️ 有  |
| VERIFY      | 读 manifest 验 stash 内容 hash 与 SCAN 一致                                                            | hash 不一致 → 反向 mv 回原位 + 报错                                            | ⚠️ 有(若 verify 失败已自动还原) |
| COMMIT      | 不删 stash,保留 24h;stdout 输出 plugin install 指引 + `--recover` 还原说明                          | —                                                                              | ✅ 完成 |

**`forge upgrade --recover`**:24h 内可调,把 stash 反向 mv 回原位 + 删 stash。  
**`forge upgrade --gc`**:删过期(>24h)stash,不影响 active stash。

**不变量**:

1. ASK 之前任何阶段都是只读,用户输 N 时 0 副作用
2. STASH / VERIFY 阶段失败必反向回滚到原位,**不允许半归还**(决策 #15 三阶段原子化继承)
3. COMMIT 后 24h 内 `--recover` 可逆;>24h `--gc` 才删 stash,给用户充分冷却期
4. 任意阶段崩 / 用户 Ctrl+C → `.claude/skills/forge-*/` + `.agents/skills/forge-*/` + `.agents/commands/forge/` + OpenCode 路径要么完整存在要么完整在 stash + manifest

**为什么不复用 transaction.ts**:transaction.ts 是"deploy 三阶段"(stage 写 → backup 旧 → commit rename),语义是"安装新文件 + 备份旧文件以防失败回滚"。upgrade 的语义是"删除旧文件 + 给恢复期",方向相反。共享代码会导致语义混淆;`forge upgrade` 自己实现 5 阶段(可复用 fs 工具函数,但状态机独立)。

### 4.2 npm CLI 版本与 plugin 版本错配

plugin 走 git URL marketplace,git pull 自动拿最新版;npm CLI 走 npm registry / 用户全局 install,版本独立。**plugin 0.3.x 调 helper 内部的 npx 拿到的可能是 0.2.x**(用户没升 npm)。

| 状态                          | 处理                                                                                                                                                                                                |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| plugin 调用前检测             | commands.md 不直接写 shell,统一调 plugin 内 helper script(见下),内部用 Node `child_process.spawn` 跑 `npx -y @accelerator-mzq/forge@^0.3 ...`,语义版本由 npx semver 解析保证                       |
| `forge` CLI 内部检测(可选,v0.4) | CLI 启动时读 `~/.claude/plugins/cache/.../plugin.json` 的 plugin 版本,major 不一致 stderr warn(本 v0.3 不做,避开循环依赖)                                                                          |

**v0.3 实施 — `scripts/run-forge.mjs` plugin helper(单点,跨 harness 复用)**:

```js
// scripts/run-forge.mjs(plugin tarball 内,不在 npm 包里)
// commands.md 调用形态:
//   - Claude Code:`node ${CLAUDE_PLUGIN_ROOT}/scripts/run-forge.mjs validate <id>`
//   - OpenCode:`node <plugin_dir>/scripts/run-forge.mjs ...`(plugin_dir 由 OpenCode 解析,Plan 0a.3 spike 验证具体形态)
//   - Codex:`node ~/.codex/forge/scripts/run-forge.mjs ...`(os.homedir() 解析,跨平台)
// bundled 变体:build 期 patch 这文件,REQUIRED_RANGE 段落改为内嵌 dist/cli/index.js 调用

import { spawn } from 'node:child_process';

const REQUIRED_RANGE = '^0.3'; // 由 build 期注入,与 plugin 版本同步

const args = process.argv.slice(2);
// Windows: spawn 找不到 'npx',需 'npx.cmd';macOS/Linux 走 'npx'
const npxBin = process.platform === 'win32' ? 'npx.cmd' : 'npx';

// npx 的 --package + 版本约束:已存在的版本满足 ^0.3 直接用;否则下载满足约束的最新版
const child = spawn(
  npxBin,
  ['-y', '--package', `@accelerator-mzq/forge@${REQUIRED_RANGE}`, '--', 'forge', ...args],
  { stdio: 'inherit', shell: process.platform === 'win32' }, // Windows 下 shell:true 解析 npx.cmd PATH
);
child.on('exit', (code) => process.exit(code ?? 1));
child.on('error', (err) => {
  console.error(`run-forge: failed to spawn npx — ${err.message}`);
  console.error(`需 Node 20+ 与 npm 7+ 在 PATH;或装 forge-bundled plugin 离线变体`);
  process.exit(127);
});
```

**好处**:

1. 版本约束由 npx semver 解析,不需自己写 `check` 工具
2. 跨 shell(Windows cmd / PowerShell / WSL bash / macOS zsh)语义一致 — 全交给 Node 处理
3. commands.md 只写一行 `node ...run-forge.mjs validate <id>`,可读
4. bundled plugin 变体改 `run-forge.mjs` 头部 `REQUIRED_RANGE` 为本地 dist/ 路径 + 内嵌调用即可,build 期一次性 patch

bundled plugin 变体跳过 npx 调用(plugin tarball 内 `dist/` 与 plugin 同版,build 期保证)。

### 4.3 SessionStart hook 失败的 fallback

| 失败模式                              | Claude Code 行为      | forge 后果                                                                                  |
| ------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------- |
| `hooks/session-start` 不可执行(权限) | hook 跳过,stderr 显示 | system prompt 无 using-forge → skill auto-trigger 仍可能命中(plugin 注册了 skills)→ 不全炸 |
| `hooks/session-start` 抛 exit 非零    | hook 输出到 stderr 显示 | 同上                                                                                         |
| hook 跑 timeout                        | Claude Code 杀进程     | 同上                                                                                         |
| `using-forge` SKILL.md 缺失           | shell `cat` 失败       | 同上                                                                                         |

**不变量**:SessionStart hook 是**加固**(让 using-forge 必然进 system prompt),不是 P0 的唯一解 — plugin 加载的 skills 本身已进 auto-trigger 池(本就是 P0 真根因解)。**双层防护**:hook 失败 → auto-trigger 仍可命中。两者都失效时,fallback 到显式 `/forge:*` slash(等价 v0.2 状态)。

### 4.4 commands 调 `npx` 失败的语义

| 场景                            | 处理                                                                                                  |
| ------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 用户机无 Node                   | npx 立刻失败,stderr 报 "需要 Node 20+",commands.md 显示给用户                                        |
| 用户机离线,首次 npx            | npm registry 不可达,npx 失败 → commands.md 报 "需要网络或装 forge-bundled" + 给 release 链接          |
| `forge validate` 退出非零       | commands.md 把 stdout/stderr 转给 AI 处理(等价 v0.2 verify 失败 → 自动 append tasks.md 路径)         |
| `forge archive` 严格门禁拒      | 退出非零,AI 看到原因 → 引导用户跑 `/forge:verify` 或 `/forge:review`                                 |

**不变量**:CLI 调用层的失败语义**与 v0.2 完全一致**(决策 #13 / #16 不变),plugin 只是换了调用方式。
