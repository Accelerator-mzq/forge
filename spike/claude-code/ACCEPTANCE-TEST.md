# Acceptance Test:Claude Code Bootstrap

**Claude Code 版本**:`2.1.126 (Claude Code)`
**测试命令**:`claude -p "我想做个 todo list 应用" --dangerously-skip-permissions`(单 turn 非交互)

## AI 响应原文

```
先把模糊需求拆清楚。todo list 这个题目太宽,不同假设会做出完全不同的东西。先问最关键的一段。

## 第 1 轮:使用场景和动机

市面上 todo 应用一抓一大把(Microsoft To Do、Todoist、滴答清单、Apple 提醒事项、Obsidian Tasks……)。你想自己做一个,通常有几种动机,你属于哪种?

**A. 学习/练手** — 重点是技术栈练习,功能只要能跑起来,作品本身不追求长期使用
**B. 自用工具** — 现有产品都不够顺手,想做个完全贴合自己工作流的(比如和你的笔记/终端/某个特定流程绑死)
**C. 产品试验** — 想验证某个特定的产品想法(比如"把番茄钟和 todo 绑一起"、"AI 自动拆解任务"、"团队异步协作"之类的差异化卖点)
**D. 给特定用户/小团队用** — 比如你和家人共享购物清单,或者小团队的轻量协作

每种动机决定的东西完全不同:
- A 选 → 我们应该挑你最想练的栈,功能砍到最小(增删改查 + 完成状态),花时间在工程质量上
- B 选 → 要先聊你**自己**现在怎么管任务、卡在哪、希望工具长什么样,功能完全围绕你的真实习惯设计
- C 选 → 要先把那个差异化想法说清楚,然后整个应用围绕它建,而不是先做"通用 todo"再加特色
- D 选 → 多人/同步/权限会成为核心,技术选型从一开始就不一样

另外顺带一个**平台**问题(可以一起回答):你想要它跑在哪里?

1. Web 应用(浏览器打开)
2. 桌面端(Windows 上的本地 app)
3. CLI(命令行,和你的 Git-Bash 工作流融合)
4. 移动端(手机上随手记)
5. 多端同步(其中两个以上)

你先回答动机(A/B/C/D)和平台(1-5),其他细节(数据存哪、UI 长啥样、要不要登录、要不要提醒……)我们后面一段一段聊,不一次性炮轰。

---

(spike 阶段还不写 `forge/drafts/2026-05-05-todo-list.md`,等我们把每一段都聊清楚后,我会把最终 design 草稿的内容**复述**给你看。)
```
